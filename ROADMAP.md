# Config Studio Roadmap & Master Architecture Plan 🗺️

План развития экосистемы **Config Studio** и официальных плагинов.

> **Главный регламент разработки:**
> 1. **Сперва ядро (Core First):** Сначала реализуются и тестируются фундаментальные механизмы ядра редактора, валидации и точек расширения.
> 2. **Предварительное обсуждение:** Перед реализацией **каждой отдельной функции** мы подробно обсуждаем ее UX/UI, структуру данных и сценарии использования. Только после явного утверждения пишется код.

---

## 🎯 ФАЗА 1: Фундамент ядра редактора («Редактор конфигов, а не IDE»)

Базовое ядро остается легковесным, быстрым и надежным. Его цель — безупречное редактирование конфигурационных файлов (`YAML`, `YML`, `TOML`, `JSON`, `JSONC`, `INI`, `CONF`, `CFG`, `.ENV`, `PROPERTIES`).

### 1.0 🔒 Безопасность ядра, песочница плагинов и аудит-лог (Security & Audit Trail)
Главное правило: **«Любое действие, затрагивающее production, должно быть явным, обратимым, журналируемым и подтверждаемым»**.
- **Манифест разрешений плагинов (Plugin Capabilities / Permissions)**:
  - Гранулярные права в `plugin.json`: `fs.read`, `fs.write`, `shell.exec`, `network`, `secrets.access`, `remote.exec`.
  - Окно подтверждения (Consent Dialog) при установке плагина (особенно из категории `community`), показывающее список запрашиваемых привилегий.
- **Встроенный журнал аудита (Core Audit Log)**:
  - Не плагин, а неотъемлемая часть ядра.
  - Фиксация всех критических событий: кто, когда, на каком сервере, какой файл изменен (с хешем diff), перезапуск служб, SSH-команды, вызовы MCP-инструментов.
- **Безопасное хранилище секретов (OS Keychain / Credential Manager)**:
  - Пароли и приватные ключи никогда не сохраняются в открытом виде в JSON. Интеграция с системным хранилищем учетных данных (Windows Credential Manager / Secret Service / Keychain).
  - В экспортируемом профиле (`config-studio-profile.json`) секреты **по умолчанию исключены**, исключая случайную утечку ключей.
- **Безопасная шина межплагинных сервисов (RPC / Proxy Bridge)**:
  - Вызовы сервисов между плагинами валидируются через защищенный мост ядра с проверкой прав вызывающего плагина, исключая подмену учетных данных из стороннего JS-кода.

### 1.1 🛡️ Глубокая валидация структуры (Structure Guard) & Pre-Save Guard
- **Градация ошибок (защита от привыкания "Alarm Fatigue")**:
  - 🛑 **Критические синтаксические ошибки (Syntax Errors)**: фатально битый синтаксис YAML/JSON, сбитые отступы, незакрытые кавычки/скобки. Для сохранения файла с критическими ошибками требуется осознанная отдельная команда **«Force Save»**, а не машинальное нажатие «ОК».
  - ⚠️ **Предупреждения совместимости (Compatibility Warnings)**: потенциальные риски (например, пробелы вокруг знака `=` в `.env` для разных рантаймов, табуляции в YAML в нестандартных контекстах).
  - ℹ️ **Стилистические замечания (Linter Hints)**: информационные подсказки без блокировки.
- **Разделение «Валидации» (Safe) и «Исполнения» (Destructive)**:
  - Валидация (`nginx -t`, `docker compose config`, проверка синтаксиса) безопасна и выполняется автоматически.
  - Исполнение (`systemctl restart`, `compose down`, деплой на сервер) требует подтверждения и предварительного показа последствий.

### 1.2 📚 Словари, автокомплит и базовые шаблоны ядра
- **Словари для конфигов:** подсказки булевых значений (`true`/`false`), номеров портов, файловых путей, переменных окружения `${VAR_NAME}`.
- **Стартовые шаблоны (New File Templates):**
  - Минимальный `.env` (типовой каркас: `APP_ENV`, `PORT`, `DB_HOST`, `SECRET_KEY`).
  - Базовый `config.yaml` / `config.toml` (секции `server`, `database`, `logging`).
  - Чистый `nginx.conf` (`server { listen 80; ... }`).

### 1.3 📦 Динамический каталог плагинов (Official / Community) и переносимые источники
- **Разделение индекса (`registry.json`):**
  - `official`: проверенные плагины ядра (`web-devkit`, `remote-agent`, `docker`, `terminal`, `makefile`).
  - `community`: плагины от сообщества с указанием автора, лицензии и плашкой *«Community»*.
  - Фильтры *«Официальные»* и *«Сообщество»* в интерфейсе настроек.
- **Портативность доверенных источников (Seamless Migration):**
  - Хранение доверенных репозиториев в файле `plugins/sources.json` (или `settings.json`) — легко скопировать на любой сервер/компьютер.
  - Функция **«Экспорт / Импорт профиля в 1 клик»**: создание файла `config-studio-profile.json` (источники, активные плагины, настройки темы без секретов) для мгновенного развертывания на новой машине.
- **Динамическое обнаружение:** опрос GitHub API доверенных организаций/пользователей по маске `config-studio-*` или топику `config-studio-plugin`.

### 1.4 ⚡ Точки расширения UI: Панель инструментов (1-Click Action Toolbar)
- **Принцип сплит-кнопки (Split Action Button):**
  - `[ ▶ Run: build | ▾ ]`: клик по левой половине мгновенно запускает действие в **1 клик** (или по горячей клавише `F5`).
  - Стрелка `[ ▾ ]` открывает выпадающий список ТОЛЬКО когда нужно переключить цель.
  - Последнее выбранное действие автоматически запоминается и становится дефолтным.
- **Строгая контекстная изоляция (`fileMatches` Guard):**
  - Плагин активирует свои кнопки только для совпавших файлов:
    - Makefile плагин: `["Makefile", "makefile", "GNUmakefile", "*.mk"]`
    - Docker плагин: `["docker-compose.yml", "compose.yaml", "Dockerfile"]`
    - Web DevKit: `[".html", ".htm", ".php"]`
  - Для обычных конфигов (`.env`, `config.json`) тулбар остается абсолютно чистым (Zero Clutter).
- **Горячие клавиши (Zero-click Hotkeys):** быстрый запуск действий с клавиатуры (`F5`, `Ctrl+Shift+B`, `Ctrl+Alt+U`).

### 1.5 💻 Постоянная нижняя полоса инструментов (Visible Bottom Dock Strip)
Решение проблемы VS Code, где терминал прячется за непонятными микро-иконками или сложными меню.
- **Постоянная видимая полоска снизу (Always Visible Dock Bar)**:
  - Внизу экрана всегда видна аккуратная тонкая статусная полоса с явными текстовыми кнопками инструментов:  
    `[ ⌨️ Терминал ]  [ 🐳 Docker Logs ]  [ 📋 Вывод ]  [ 🔍 Проблемы ]`.
  - Никаких скрытых кнопок: пользователь **всегда четко видит, где находится терминал**, и не тратит время на поиск.
- **Интуитивное управление в 1 клик**:
  - Клик по кнопке `[ ⌨️ Терминал ]` — панель плавно выезжает снизу (кнопка подсвечивается акцентным цветом как активная).
  - Повторный клик по активной кнопке (или кнопке `[X]`) — панель мгновенно сворачивается обратно в компактную полоску.
  - Переключение между инструментами (например, с Терминала на Docker Logs) происходит в 1 клик прямо на полосе.
- **Плавный ресайз и пресеты высоты**:
  - Drag-сплиттер для плавной регулировки высоты мышью + кнопки быстрого переключения высоты (240px / 420px / во весь экран).
  - Сохранение высоты и последнего состояния в `settings.json`.
- **Горячие клавиши**: быстрый вызов последнего активного инструмента по комбинации `Ctrl+` ` и `Ctrl+J`.


### 1.6 🖱️ Слот расширения контекстного меню проводника (Context Menu Provider)
- Возможность плагинам регистрировать свои пункты контекстного меню при правом клике на файл в дереве проводника.

### 1.7 🔗 Система зависимостей плагинов (Plugin Dependencies & Inter-Plugin Services)
- **Декларация зависимостей в манифесте `plugin.json`**:
  ```json
  "dependencies": {
    "config-studio-ssh": ">=1.0.0",
    "config-studio-remote-agent": ">=1.1.0"
  }
  ```
- **Автоматическая установка зависимостей**:
  - При установке плагина ядро проверяет зависимости. Если нужного плагина нет в системе, выводится диалог:  
    *«Для работы "Quick Agent Install" требуются плагины: "SSH Client" и "Remote Server Agent". Установить их автоматически?»*.
- **Защита от сбоев и каскадного удаления**:
  - Запрет на отключение или удаление плагина, если от него зависят другие активные плагины (с понятным объяснением, какой плагин требует его работы).
- **Топологический порядок загрузки (DAG)**:
  - Ядро выстраивает граф зависимостей и гарантирует, что плагины-провайдеры сервисов инициализируются раньше зависимых потребителей.
- **Реестр межплагинных сервисов (Inter-Plugin Service Registry)**:
  - Экспорт и импорт общих возможностей через единую шину ядра:  
    `window.ConfigStudio.services.register('ssh', sshService)` и `window.ConfigStudio.services.get('ssh')`.

## 🧩 ФАЗА 2: Модульная экосистема официальных плагинов


Каждый плагин создается как **независимый репозиторий** и устанавливается пользователем только при необходимости.

### 2.1 📁 Плагин: Расширенные операции проводника (`config-studio-explorer-plus`)
- 📋 **Буфер обмена (`Ctrl+C`, `Ctrl+X`, `Ctrl+V`)**: копирование, вырезание и вставка файлов и папок с авторазрешением коллизий имен.
- 📑 **Дублирование в 1 клик**: клонирование файла с суффиксом (`config.yaml` ➔ `config_copy.yaml`).
- 🛡️ **Быстрый снимок (.bak)**: мгновенная резервная копия перед опасными правками (`nginx.conf.bak`).
- 🖱️ **Полноценное контекстное меню по правому клику**: *Открыть*, *Копировать/Вставить/Вырезать*, *Дублировать*, *Бэкап*, *Копировать путь*, *Свойства/История*, *Удалить*.
- 🗂️ **Множественный выбор (Multi-select)**: `Shift`/`Ctrl` для групповых операций.

### 2.2 🐳 Плагин: Docker & Compose Manager (`config-studio-docker`)
- 🚀 Прямые кнопки тулбара: **Compose Up (`-d`)**, **Compose Down**, **Compose Pull & Restart** в 1 клик.
- 📋 **Live Logs Viewer**: стриминг stdout контейнеров в нижнюю панель в реальном времени.
- 🔍 **Status Dashboard**: список контейнеров, статусы портов, рестарт отдельных сервисов.
- 💡 Сниппеты для директив Compose и Outline-дерево сервисов.

### 2.3 🔨 Плагин: Запуск сценариев сборки Makefile (`config-studio-makefile`)
- 🎯 Активация строго по маске: `fileMatches: ["Makefile", "makefile", "GNUmakefile", "*.mk"]`.
- 🔍 Автопарсинг всех целей (`build`, `test`, `run`, `deploy`, `lint`, `clean`) и комментариев к ним.
- 🚀 Сплит-кнопка запуска в тулбаре `[ ▶ Run: build | ▾ ]` + кликабельные цели в дереве Outline.
- 📋 Стриминг выполнения в нижнюю панель (Bottom Dock) с цветным выводом и кодом завершения.

### 2.4 📡 Плагин: Remote Server Agent — Broadcast & Multicast (`config-studio-remote-agent v2`)
- 🏷️ Тегирование и группы серверов (`prod`, `staging`, `edge`, `backend`).
- 📡 Синхронная рассылка конфига на несколько или все серверы.
- 🛡️ **Интерактивный экран подтверждения (Approve Modal)**:
  - Визуальный просмотр Diff (изменений).
  - Pre-flight детекция дрифта (проверка хешей на удаленных серверах перед деплоем без возможности случайного обхода).
  - Выборочное включение/исключение серверов чекбоксами.
  - **Canary-first стратегия**: безопасная раскатка сначала на 1 сервер / группу canary, автоматическая проверка живости (health check), и только затем batch-деплой на остальной парк.
  - Обязательный **Rollback-план в 1 клик** (автоматический откат к `.bak` копии при сбое).
  - Кнопка **«Approve & Deploy»** с записью операции в единый журнал аудита ядра.

### 2.5 🌐 Плагин: Веб-разработка (`config-studio-web-devkit v1.2`)
- 🖥️ **Имитация вкладки браузера над превью (Browser Tab & Chrome Bar Preview)**:
  - Прямо над окном живого предпросмотра отображается стилизованная панель реальной вкладки браузера (Chrome / Edge style):
    - **Фавиконка**: живой вывод иконки сайта из `<link rel="icon" ...>` (или дефолтный глобус).
    - **Заголовок страницы**: живой вывод текста из `<title>...</title>` прямо во вкладке (обновляется на лету при наборе кода в редакторе).
    - **Адресная строка**: компактная строка адреса (`http://localhost:8085/page.html`) с кнопкой перезагрузки `[🔄]` и индикатором статуса.
  - Позволяет разработчику сразу видеть, как вкладка страницы будет смотреться в реальном браузере у конечного пользователя.
- 📚 **Словари и автодополнение**: теги и атрибуты HTML5, функции и суперглобальные массивы PHP (`$_POST`, `$_GET`, `pdo`, `json_encode`).
- 🛡️ **Проверка структуры**: DOM-валидация закрытия тегов и синтаксический чекер PHP для исключения Parse Error.
- 📄 **Стартовые шаблоны**: валидный HTML5 Boilerplate и базовый `index.php`.


### 2.6 🖥️ Плагин: Встроенный терминал и CLI (`config-studio-terminal`)
- Полноценная эмуляция терминала на базе **xterm.js** в нижней панели.
- Двусторонний WebSocket PTY-стриминг (PowerShell, Bash, Zsh).
- Поддержка локального шелла и удаленного доступа к серверам через `remote-agent`.
- Интеграция с существующей защитой от деструктивных команд (`CommandConfirmModal`).

### 2.7 🤖 Плагин: Сервер Model Context Protocol (`config-studio-mcp`)
- Превращение Config Studio в официальный MCP-сервер для внешних ИИ (Claude Desktop, Cursor, Antigravity, локальные LLM).
- 🔒 **Security-first модель доступа для AI**:
  - **Read-only по умолчанию**: AI-ассистенты могут безопасно анализировать открытые конфиги, выполнять синтаксические проверки и запрашивать метаданные.
  - **Human-in-the-Loop для деструктивных действий**: любые мутации (запись в файл, `shell.exec`, удаленный деплой, перезапуск демонов) блокируются до явного подтверждения человеком в диалоге с показом полного diff и параметров.
- Инструменты безопасного чтения, валидации структуры AST и генерации diff конфигов.

### 2.8 🔑 Плагин: SSH Клиент и менеджер подключений (`config-studio-ssh`)
Автономный модуль безопасного SSH/SFTP взаимодействия с удаленной инфраструктурой.
- **Гибкая аутентификация**:
  - Подключение по SSH-ключам (OpenSSH `id_rsa`, `id_ed25519` с парольными фразами или без).
  - **Подключение по логину и паролю (Password Authentication)** с опцией безопасного сохранения паролей.
- **Сетевые возможности**: поддержка кастомных портов, таймаутов, keep-alive и Jump Host (bastion серверов).
- **Экспорт сервиса для других плагинов (`services.get('ssh')`)**:
  - `exec(hostConfig, command)` — выполнение удаленных скриптов.
  - `upload(hostConfig, localPath, remotePath)` — надежная передача файлов по SFTP.
  - Интерактивный терминальный мост для консоли `config-studio-terminal`.

### 2.9 ⚡ Плагин: Быстрое пакетное развертывание агентов (`config-studio-quick-agent`)
Массовая установка и привязка агентов к парку серверов в 1 клик.
- **Зависимости**: требует установленные и активные плагины `config-studio-ssh` и `config-studio-remote-agent`.
- **Конфигурация серверов: Строго YAML или JSON**:
  - Полный отказ от устаревших форматов вроде CSV в пользу нативных, понятных человеку форматов.
  - ⚓ **Использование якорей YAML (Anchors & Aliases — DRY принцип)**:
    - Блок аутентификации (SSH-ключ или пароль, порт, дефолтный пользователь) описывается **ровно один раз** через якорь `&shared_auth`:
      ```yaml
      defaults: &default_ssh
        user: root
        port: 22
        auth:
          type: key
          key_path: ~/.ssh/id_ed25519 # или type: password, password: secret

      servers:
        - host: 192.168.1.10
          name: prod-web-01
          tags: [prod, web]
          <<: *default_ssh

        - host: 192.168.1.11
          name: prod-web-02
          tags: [prod, web]
          <<: *default_ssh

        - host: 192.168.1.20
          name: staging-db
          tags: [staging, db]
          user: ubuntu # переопределение поля при необходимости
          <<: *default_ssh
      ```
    - Для JSON: поддержка секции `"defaults"` с наследованием общих параметров аутентификации.
- **Автоматический процесс развертывания («Install & Enroll»)**:
  1. Параллельное подключение к серверам через плагин `config-studio-ssh` с использованием общего ключа/пароля из якоря.
  2. Определение архитектуры узла (Linux x86_64, arm64, debian, rhel, alpine).
  3. Заливка бинарника `config-studio-agent` по SFTP.
  4. Автоматическая настройка systemd-сервиса (`systemctl enable --now config-studio-agent`).
  5. Генерация уникального auth-токена и проверка liveness.
### 2.10 🔄 Плагин: Менеджер служб Systemd (`config-studio-systemd`)
Управление жизненным циклом демонов и сервисов прямо из открытого конфига.
- **Автодетекция службы**: при открытии конфига (например, `nginx.conf`, `redis.conf`, `postgresql.conf`, `/etc/systemd/system/*.service`) плагин определяет ассоциированный systemd-юнит.
- **Кнопки управления в 1 клик**:
  - `[ 🔄 Reload ]` — мягкая перезагрузка конфигурации сервиса без разрыва соединений.
  - `[ ⏹ Restart ]` — полный перезапуск демона.
  - `[ 🔍 Status ]` — мгновенный просмотр `systemctl status <unit>`.
- **Автоматический просмотр Journalctl**: при перезапуске в нижнем доке автоматически всплывают последние 25 строк `journalctl -u <unit>`, чтобы убедиться, что служба поднялась без сбоев.

### 2.11 🌐 Плагин: Валидатор веб-серверов и SSL (`config-studio-nginx`)
Специализированная защита для администраторов веб-серверов (Nginx, Caddy, Traefik, Apache).
- **Безопасный перезапуск (`nginx -t` Guard)**:
  - Автоматическая проверка синтаксиса `nginx -t` **перед** сохранением файла или перезапуском сервиса.
  - Если в директивах опечатка — сервис не перезапускается, веб-трафик не ложится, а пользователь видит строку с ошибкой.
- **Переключатель сайтов в 1 клик**:
  - Управление виртуальными хостами: включение и выключение сайтов через симлинки `sites-available/` ➔ `sites-enabled/` прямо из проводника.
- **Инспектор SSL/TLS сертификатов**:
  - Плашка в тулбаре с датой истечения SSL-сертификата (`Let's Encrypt: осталось 14 дней`).

### 2.12 📊 Плагин: Монитор здоровья сервера в Status Bar (`config-studio-sysinfo`)
Компактный индикатор состояния текущего подключенного сервера прямо в нижней строке состояния.
- **Метрики в реальном времени**: CPU Load %, RAM Used %, Свободное место на диске `/`, Uptime.
- **Disk Space Guard**: если на сервере осталось менее 5% свободного места, плагин выдает предупреждение перед созданием бэкапов и сохранением файлов.

### 2.13 📜 Плагин: Просмотр логов Journalctl & Syslog (`config-studio-journal`)
Удобный стример серверных логов в нижнюю панель (Bottom Dock).
- Стриминг файлов `/var/log/*` и системного журнала `journalctl -f`.
- Фильтрация по уровням важности (`ERROR`, `WARN`, `INFO`), текстовый поиск с регулярными выражениями и кнопка паузы/автоскролла.

### 2.14 ⏰ Плагин: Визуальный планировщик Cron & Timers (`config-studio-crontab`)
Редактирование задач cron (`crontab -e`, `/etc/cron.d/*`) и таймеров systemd.
- Перевод cron-выражений на понятный человеческий язык (например: `0 3 * * 1` ➔ «Каждый понедельник в 03:00»).
- Расчет и наглядное отображение времени следующего запуска задачи.

## 🖥️ Будущее настольное клиентское приложение (Desktop App Foundation)

Пока разработка сосредоточена на веб-интерфейсе, однако кодовая база React + Go изначально проектируется с прицелом на легкую упаковку в автономный десктопный клиент.

### Выбор движка для настольного приложения (Desktop Engine Evaluation):
Финальный выбор движка будет сделан в Фазе 3 на основе реального прототипа и замеров производительности на целевых ОС:
1. **Wails (Go + Native Webview) — Приоритетный кандидат:**
   - Поскольку весь бэкенд Config Studio уже написан на Go, Wails позволяет скомпилировать нативное приложение напрямую, повторно используя существующий Go-код без переписывания и лишних прослоек.
   - Использует системный движок рендеринга (Edge WebView2 на Windows, WebKitGTK на Linux, WebKit на macOS), что дает компактный размер бинарника.
2. **Tauri v2 (Rust / C + Native Webview):**
   - Ультралегкий фреймворк с жесткой встроенной моделью разрешений и безопасной изоляцией процессов.
3. **Electron (Node.js + Chromium):**
   - Классический стандарт индустрии (как VS Code, Discord, Slack). 100% предсказуемый рендер, но большой вес сборки и высокое потребление ресурсов.

### Гибридная модель работы:
- **Настольный клиент:** работает в своем окне, хранит защищенные SSH-ключи, базу `servers.yaml` и токены в системном хранилище (`%APPDATA%/config-studio`).
- **Связь с агентами:** настольный клиент одинаково прозрачно подключается:
  - К **Headless-агентам** на серверах (где веб-интерфейс выключен ради экономии ресурсов и безопасности).
  - К **Web-агентам** (где веб-интерфейс включен флагом `--web` для экстренного доступа через браузер).
